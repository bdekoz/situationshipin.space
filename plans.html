Plans are written in the izzi repository and published here with one approval-gated command. This page never creates or submits anything itself.

01

Scaffold

One command in izzi turns a name and a one-line concept into a starter plan draft.

02

Write to the stage

Start cheap as a draft; add template, segments, estimates, pilot options, gates, then orchestration as formality grows.

03

Publish

Run the approval-gated publisher from the situationshipin.space repository, then commit and push. The plan appears here newest-first.

Stage requirements
Stage Required before publishing
draft Provenance and a bounded document only — no required sections, no PDF, no house-style checks.
vertical Template, segments, estimates, pilot options, and gates in the plan content.
formal Adds orchestration; a PDF variant must carry a PASS special-topics check supplied with --checks.

A KEEP on an earlier stage advances the plan; a KEEP on the formal plan unlocks that vertical's draft loop.

Publish command 
node scripts/publish-plan-proof.mjs \
  --approve PROJECT-APPROVED \
  --source docs/development/<vertical>/proposal_vertical_v2.md \
  --source-path docs/development/<vertical>/proposal_vertical_v2.md \
  --artifact-id plan-vertical-<slug>-v2 \
  --title "<Vertical> — proposed vertical v2" \
  --description "What the plan reviewer should confirm" \
  --family <family> \
  --feedback-round plan-v2 \
  --stage vertical

Run with --dry-run first to preview without writing. --approve PROJECT-APPROVED is the explicit project approval gate; without it the publisher refuses. Plan documents are capped at 16 MiB.
